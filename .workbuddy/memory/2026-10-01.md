# 2026-10-01

## 项目梳理：STAR 拆解 + DAG 计划模拟

### 做了什么
1. 通读项目（README、pyproject、9 份 docs 设计文档、orchestrator 核心代码），产出 STAR 拆解。
2. 模拟 Agent 输出的 DAG 计划，产出 `output/dag_simulation.html`（原始 JSON + 控制台面板 + DAG 图 + 批次调度表）。

### 梳理出的关键事实（供后续会话复用）
- **编排**：`planner.py`（LLM 出 JSON）→ `executor.py`（Kahn 拓扑分层 + asyncio.gather）→ `main_agent.py::_synthesize`（LLM 汇总）。LLM 不参与执行决策。
- **Plan 数据结构**：`Plan{goal, steps[]}`，`PlanStep{id, tool, description, query, depends_on[], fallback_for?}`。
- **校验规则**：`_validate()` 检查工具存在性、依赖存在性、自依赖、DFS 环检测，且文件生成工具必须 depends_on 所有 info 工具。
- **`fallback_for` 兜底机制**（docs 里没写，代码里新增）：executor 读上游 step 的 code，HIT 则跳过兜底步并直接记 HIT，`needs_fallback()`（shared/agent_result.py）判定 MISS/ERROR 才真执行。
- **端口现状**：8000 编排 / 8001 搜索 / 8002 数据库 / **8003 RAGFlow（已注释禁用）** / 8004 向量 / 8005 记忆 / 8100 MySQL MCP。
- **重要不一致**：`call_ragflow_query` 在 `a2a_tools.py`、`executor.py`、`planner.py::_default_tools` 中均为注释禁用，由 `call_vector_search` 替代；但 `docs/main_agent决策纠偏.md` 整篇仍在讲 RAGFlow 优先。读这些文档时需注意时效性。

### 环境注意
- 本机 bash 不可用（`ls`/`find`/`mkdir` 均 not found），请改用 PowerShell 或 Read/Glob/Grep/Write 工具。
- PowerShell 直接输出也常被吞，建议优先用 Glob/Read 浏览文件。
